# 架构与数据一致性

原生小程序只负责展示、输入及请求。`utils/api.js` 在 `local` 下发 HTTP 请求，在 `cloud` 下调用微信云函数；二者调用相同 `server/service.js`。所有权威身份、状态、人数、时间和冲突校验均在服务端。任何客户端 `role`、`isAdmin`、`status` 或用户 ID 都不授予权限。

## 数据表

| 表 | 关键字段和约束 |
|---|---|
| users | id 主键；data 包含核验资料；已通过 studentNo 部分唯一索引 |
| rooms | 房间ID主键；五间固定容量/设备按Pixso；settingsVersion支持已有资料无损升级 |
| admin_grants | user_id 主键/外键；独立授权来源 |
| identity_reviews | id、user_id 外键；资料快照、状态、处理人/时间/原因；待办状态索引 |
| reservations | id、user_id/room_id 外键；data 为业务快照；状态枚举、正人数、起止顺序 CHECK；房间日期/归属状态索引 |
| idempotency | 用户作用域请求键的散列主键、user_id 外键、输入摘要及原预约 ID |
| audit_logs | 操作者、对象、动作、原因及时间；不记录令牌或校园密码 |
| feedback | 本人user_id外键、类型、正文、处理状态/回复、处理人/时间；用户作用域请求键唯一索引，启用RLS无客户端策略 |
| sessions | 本地令牌SHA256哈希、user_id外键和有效期，启用RLS；不存原始令牌 |
| app_lock | 固定 id=1，数据库级并发互斥行 |

JSONB 便于五周课程演示保存资料和预约快照；用户/房间关系、唯一性、预约状态及基本数据合法性仍有 SQL 约束。业务层只更新变化记录，不清空表或重写整个数据库。所有业务表启用 RLS，无客户端策略，并撤销 PUBLIC 权限。服务端使用表所有者或已授权 BYPASSRLS 角色。

## 一次预约事务

1. `BEGIN ISOLATION LEVEL READ COMMITTED`。
2. `SELECT id FROM app_lock WHERE id=1 FOR UPDATE`，跨云函数实例也锁同一数据库行。
3. 获取锁后读取最新业务状态，按服务端当前时间计算失效/完成，检查请求幂等摘要。
4. 校验已核验身份、房间、字段、容量、北京时间及冲突；冲突判据 `new.start < old.end && new.end > old.start`。
5. 在同一事务写预约、幂等映射和最低限度操作日志，再 `COMMIT`；任何错误 `ROLLBACK`。

取消、预约审批、身份审批也走同一锁，因此不能与创建交错形成不一致。教师不能覆盖学生已待确认时段。PGlite 只有一条连接，外层队列防止 BEGIN 交错；云端正确性来自 PostgreSQL 行锁，不能用进程内队列代替。所有业务写入必须走此事务入口，数据库控制台人工写入须停业务并复核一致性。

代价是查询和所有房间操作也串行、全量读取历史。适合五房间课程验证，**没有生产吞吐承诺**。正式数据量增长应改为按房间/日期锁、数据库函数/范围约束、分页与限流，不在本项目中引入微服务。

## 状态与时间

状态为 pending、approved、rejected、cancelled、expired、completed。学生提交 pending，教师 approved。pending 在 `startAt <= now` 时有效状态为 expired；approved 在 `endAt <= now` 为 completed。服务端每个请求使用同一判断，即使落库整理未执行也不错误阻塞或逾期批准。事务报错回滚了整理字段，不会改变下一请求重新计算的结果。课设未部署独立定时任务。

存储 epoch 毫秒；日期解析明确 `+08:00`，业务口径 Asia/Shanghai，与运行主机时区无关。日期合法性通过实际日历回算校验；只接受 HH:mm，开始严格晚于服务器当前时间，08:00—22:00 内无额外时长上限，相邻允许。

## 身份边界

本地测试账号使用随机256位令牌，默认仅回环监听，令牌哈希和12小时有效期保存在数据库，进程重启不再丢失有效登录。显式执行`start:lan`才启用局域网演示：须绑定电脑私有IPv4并配置手机地址允许列表，在进入接口前按socket来源地址校验，不接受请求体或代理头伪造来源。云函数不包含测试登录路由，根据 `getWXContext()` 的 OPENID/APPID 生成内部 ID；首次登录仅创建未核验账号。人工批准才赋师生身份。首位管理员由运维 CLI 授权，管理员本人预约仍取其师生身份。学校 SSO 接入点为会话/身份适配层，尚未获得接口授权。

## 部署与恢复

CloudBase 包只包含共享服务及 PostgreSQL 驱动，未依赖云函数本地磁盘。先初始化数据库，再部署云函数；修改共享代码后必须 `cloud:prepare`，结构检查会校验副本。运行环境与测试数据库、开发账号独立。数据库备份和恢复由云环境负责人按批准的保留制度配置；本项目没有替用户开通任何付费资源。
