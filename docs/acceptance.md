# 手工验收步骤

本表为待在微信开发者工具/真机执行的步骤，不冒充已经完成的设备验证。可执行本地验证见 test-report.md。

## 用户端

1. 启动 README 本地服务并导入根目录。检查环境横幅清晰写“本地开发/测试数据”，首页沿用校园背景、快捷入口、日历、五房间和底部导航。
2. 学生甲登录，选择未来日期。进入7081，选择09:15—11:45，填用途、8人、格式电话；提交应为待确认，不能显示已审批成功。
3. 同日首页显示红色区间；切换次日不应保留旧占用。时间条与详情占用文本一致，查看他人占用不显示姓名、电话或用途。
4. 教师试约同房重叠区间应冲突；11:45开始应允许。人数13应拒绝；7060人数正整数允许并显示容量待核实。
5. 在“我的预约”全部/待确认/已通过/已取消及日期筛选，核对详情、原因。取消须二次确认，开始后不可自助取消，取消历史仍保留。
6. 断网提交，恢复后保持内容重试；检查原请求ID重用、不产生重复。也可到我的预约确认最终结果。
7. 未核验用户不可查日程；提交测试教师身份仍不可预约，负责人通过后才可直约。拒绝后原因可见、可重提。

## 管理员端

1. 测试负责人在“我的”看到管理工作台，普通师生没有入口。直接调用管理接口仍须后端授权。
2. 待办显示未开始的学生申请，查看详情后批准；拒绝必须填写原因，拒绝后时段释放。
3. 预约台账组合房间、日期、状态、申请人姓名或学工号；仅负责人能看到必要联系方式和用途。
4. 两个负责人同时操作同一待办；最多一次成功，另一个显示最新状态/冲突，不重复审批。
5. 测试负责人自身作为学生提交时仍应待确认，不能因管理权限直接成功。

## 时间与设备

1. 将专用测试环境预约设置为未来几分钟，到开始瞬间再批准/取消待确认记录，须失效并不可再批准；已成功记录到结束时完成。
2. 440×956、375×812各一模拟器尺寸：无横向溢出，卡片文字可读，时间选择器可选择任意分钟，底部导航正常。
3. 至少一个真实手机通过云环境走学生、教师、管理闭环，复查安全区、键盘遮挡、滚动和错误重试。
4. 云环境测试不能使用电脑127.0.0.1；需已授权AppID和CloudBase环境。未执行前表格记录为“未验证”。
